# SPEC 23 — Marcy the Vampire Hunter: the Credit Coin drop (Pin Collection credits)

> **Status:** Implemented
> **Depends on:** SPEC 13, SPEC 18, SPEC 20, SPEC 21, SPEC 22
> **Date:** 2026-11-10
> **Objective:** Add a rare item to Marcy the Vampire Hunter, the Credit Coin, with a flat 0.1% chance on every enemy kill, breakable, chest and boss death, that gives a signed-in player 1 Pin Collection credit through the existing `award_boss_credit` RPC.

## Why this spec exists

SPEC 21 and SPEC 22 first planned a SPEC 23 for spells and familiars. The user replaced it: the game now has a lottery-like surprise that feeds the site's Pin Collection (`/pins`, the `CREDITS · NN` pill in the nav). **Spells and familiars are out of scope** and no spec is planned for them. SPEC 21 and SPEC 22 were updated to say so; the 26 password bits first reserved for spells and familiars stay spare.

Credits are a database value that no client can write (SPEC 18). Robo Vault already solved this with the RPC `award_boss_credit` and the table `boss_awards` (SPEC 20 amendments): the client reports an event and the server rate-limits. The user chose to **reuse that RPC** for the Credit Coin instead of creating a new one, so this spec extends it with a second game and a `drop` event.

## Scope

**In:**

- **Credit Coin item.** A pickup (own pixel sprite: a pale silver coin with a bat emblem, a small glint) that appears where a drop would appear. Walking into it collects it. It bobs in place, lives 12 s on the engine clock (blinks during the last 3 s) and disappears when the room changes. Collecting it plays the new effect `credit` and fires `onCreditDrop`.
- **Drop rule.** Every drop opportunity makes one separate roll of `CREDIT_DROP_CHANCE = 0.001` (0.1%), independent of the normal drop table (the normal drops do not change). Drop opportunities in both castles (SPEC 21 main castle and SPEC 22 Turned Castle):
  - an enemy dies;
  - a breakable object breaks (candles, urns, and every other breakable that can hold an item);
  - a chest opens (its fixed content stays; the Credit Coin is an extra roll);
  - a boss dies (its fixed reward stays; the Credit Coin is an extra roll).
    The chance is flat: LCK, level, hero and castle do not change it. The engine uses `Math.random()`.
- **Signed-in players only (user decision).** The engine rolls only when `canDropCredit()` returns `true`. `GamePlayer` supplies it from the session (`signedIn`). A guest never sees a Credit Coin. The callback is read at every roll, so the engine does not need to know the session state when it is created.
- **Award.** `GamePlayer` receives `onCreditDrop`, calls `awardDropCredit(gameId)` (new in `lib/pins-db.ts`, same RPC as boss credits with `p_boss = "drop"`), updates the nav balance (`setBalance`) and shows the notice `CREDIT COIN +1 CREDIT` over the CRT (same notice component and timer as the Robo Vault boss notice, with its own text). The game-over `+N CREDITS` line adds these credits to the play-time and boss credits.
- **Server (migration).** One migration that replaces `award_boss_credit(p_game_id, p_boss)` with a version that keeps every Robo Vault rule and also accepts `p_game_id = 'marcy-vampire-hunter'` with `p_boss = 'drop'` only. The Marcy game awards nothing for bosses (boss ids are rejected for it). The user's choice reuses the existing rate limits (at least 3 s between awards, at most 30 per rolling 24 h per user, banned users get nothing, reasons `ok` / `banned` / `too_soon` / `daily_cap`), and the limits are shared with Robo Vault boss credits because they use the same `boss_awards` log. The `boss_awards.boss` column stores `drop`.
- **New sound.** `credit.wav` (a short bright two-note chime with a faint bell tail, gothic mood, volume 0.2). The sound list becomes 19 effects (17 from SPEC 21, `turn` from SPEC 22, `credit` here). Generated by the same kind of one-off Node script, not shipped.
- **Docs.** Update `CLAUDE.md` (Credit Coin, extended RPC, `GameCanvasProps` additions, 19 sounds) and `references/GAMES.md`.
- UI (coin sprite, notice text) designed with `/frontend-design`.

**Out of scope (for future specs):**

- Spells and familiars (no spec planned).
- A new RPC, a new table, a change to the limits of `award_boss_credit` for Robo Vault, a guest credit.
- Boss credits for Marcy the Vampire Hunter (only the Credit Coin gives credits here).
- LCK bonus, pity timer, per-run limits or a visible counter of coins found.
- Saving the coin in the password (a collected coin is a database value, not progress).
- Pin Collection pins for this game, changes to the Pin Collection UI, the `pull_pin` or `award_credit` RPCs.
- Other credit amounts (one coin = 1 credit), a second coin type.
- Automated tests.

## Data model

Database. No new table or column. One migration `supabase/migrations/<version>_award_boss_credit_marcy_drop.sql` (version assigned by `apply_migration`, later than `20261111044618` and later than the SPEC 21 `add_marcy_vampire_hunter_game` migration, since the game row must exist before an award can reference it) that runs `create or replace function public.award_boss_credit(p_game_id text, p_boss text)` with these validation changes only:

```sql
if p_game_id is not distinct from 'robo-vault' then
  if p_boss is null
     or not (p_boss ~ '^(rematch:)?(frostbyte|embercore|galeforce|tidebreaker)$' or p_boss = 'sam') then
    raise exception 'invalid_boss';
  end if;
elsif p_game_id is not distinct from 'marcy-vampire-hunter' then
  if p_boss is distinct from 'drop' then
    raise exception 'invalid_boss';
  end if;
else
  raise exception 'unknown_game';
end if;
```

Everything else in the function (advisory lock, banned check, 3 s and 30 per 24 h limits, insert into `boss_awards`, credits upsert, JSON result) is copied unchanged. `revoke execute ... from public, anon` and `grant execute ... to authenticated` are repeated. `get_advisors` shows no new warning (the function is already an accepted definer warning). The migration is applied with MCP `apply_migration` and no type regeneration is needed (the signature is unchanged). Every database change stays in a migration file.

Engine additions (`lib/vampire-hunter/`):

```ts
// constants.ts
export const CREDIT_DROP_CHANCE = 0.001; // 0.1% per drop opportunity
export const CREDIT_COIN_LIFETIME = 12; // seconds on the engine clock
export const CREDIT_COIN_BLINK = 3; // last seconds blink

// engine.ts
export type VampireHunterSound = /* SPEC 21 and 22 sounds */ "credit";

export interface VampireHunterCallbacks {
  // ...SPEC 21 and 22 callbacks...
  onCreditDrop?: () => void; // fired once per collected Credit Coin
  canDropCredit?: () => boolean; // false for guests: no roll, no coin
}
```

`entities.ts` gets the `creditCoin` pickup kind and its sprite (run table, drawn at x3, at most 6 colors). `utils.ts` gets `rollCreditDrop(random = Math.random)` returning `true` with probability `CREDIT_DROP_CHANCE`; the drop code in `engine.ts` calls it once per drop opportunity and never changes the normal drop result.

Client:

```ts
// lib/pins-db.ts
export async function awardDropCredit(gameId: string): Promise<BossAwardResult>;
// same RPC as awardBossCredit, with p_boss = "drop"
```

```ts
// components/game-registry.tsx (GameCanvasProps, optional, additive)
onCreditDrop?: () => void;
canDropCredit?: () => boolean;
```

`components/vampire-hunter-canvas.tsx` forwards both through its callbacks ref (so a session change after mount is read at the next roll). `components/game-player.tsx` passes `onCreditDrop` and `canDropCredit` to the canvas next to `onBossDefeated`.

Rules and conventions:

- Everything of SPEC 21 and SPEC 22 holds (engine clock, callbacks only on change, no sound from the engine, `lib/vampire-hunter/` imports nothing from `react` or `next`).
- The coin pickup freezes while paused and while the in-canvas menu is open (engine clock).
- The award is sent when the coin is collected, never when it drops. A coin that expires or is left behind awards nothing.
- A failed RPC call, a `too_soon`, `daily_cap` or `banned` result shows nothing (same as boss credits); the coin is still consumed.
- The notice text is English: `CREDIT COIN +1 CREDIT`.
- No `localStorage`, cookie or password bit is used for the coin.

## Implementation plan

Before step 1, read the relevant guides in `node_modules/next/dist/docs/` if a step touches pages or caching (normally not). Invoke `/frontend-design` for the coin sprite and the notice.

1. **Migration.** Write the migration file, apply it with MCP `apply_migration`, rename the file to the version the tool assigns, run `get_advisors`. Verify with `execute_sql` that the function body accepts `('robo-vault', 'sam')` and `('marcy-vampire-hunter', 'drop')` and raises `invalid_boss` for `('marcy-vampire-hunter', 'sam')` and `unknown_game` for any other id (each check inside a transaction that is rolled back, or as a signed-in test user, never leaving rows in `boss_awards`).
2. **Client call.** Add `awardDropCredit` to `lib/pins-db.ts`. `npm run lint` and `npm run build` pass.
3. **Engine, constants and roll.** Add the constants, `rollCreditDrop` in `utils.ts`, the `creditCoin` pickup kind and sprite, the `credit` sound id, and the `onCreditDrop` and `canDropCredit` callbacks. Folder imports nothing from `react` or `next`.
4. **Engine, drop opportunities.** Call the roll at enemy death, breakable break, chest open and boss death (main and Turned Castle); spawn the coin at the drop position; collect, expire and clear on room change; fire `onSound("credit")` and `onCreditDrop()` on collect.
5. **Canvas wrapper and `GamePlayer`.** Forward the callbacks, add the optional `GameCanvasProps`, pass `onCreditDrop` (calls `awardDropCredit`, updates the balance, shows the notice, adds to the game-over credits) and `canDropCredit` (`signedIn`). Check that Robo Vault and the other games are unchanged.
6. **Audio.** Generate `credit.wav` with a one-off Node script (not shipped) into `public/game-assets/marcy-vampire-hunter/`; add `credit` to the registry `sfx` (19 sounds). Check by ear: it differs from `pickup` and `relic`.
7. **Walkthrough.** In `npm run dev` with Playwright (captures only in `.pwScreencaps/`): temporarily set `CREDIT_DROP_CHANCE` to `1` locally (never committed), kill an enemy, break a breakable, open a chest and kill a boss in each castle, and confirm a coin each time; collect one as a signed-in user and confirm `+1` in the nav pill, the notice, a `boss_awards` row with `boss = 'drop'` and the game-over `+N CREDITS` line; confirm that a guest gets no coin; collect two coins within 3 s and confirm the second shows nothing; let a coin expire and leave a room with one. Restore the constant to `0.001` and check by grep that the committed value is 0.001.
8. **Docs.** Update `CLAUDE.md` and `references/GAMES.md`. Run `npm run lint` and `npm run build`.

- [ ] All 10 other games behave exactly as before; Robo Vault boss credits still award with the same limits and reasons.
- [ ] No `localStorage` key, cookie or extra table is written; `lib/storage.ts` is unchanged.
- [ ] `lib/vampire-hunter/` imports nothing from `react` or `next`.
- [ ] No text is in Spanish; no Konami asset, name or melody is used.
- [ ] No React hydration warnings on reload; no `mix-blend-mode`, animated `mask-image` or full-screen animated layer was added.
- [ ] EXIT or leaving the page stops the engine and the music: no loop and no listener remains.

Game-specific:

- [ ] `CREDIT_DROP_CHANCE` is `0.001` in the committed code and nothing reads another value.
- [ ] A drop opportunity is an enemy death, a breakable break, a chest open or a boss death, in the main castle and in the Turned Castle; each makes exactly one extra roll and the normal drops are unchanged.
- [ ] A guest never sees a Credit Coin (`canDropCredit` returns `false`); a signed-in player can.
- [ ] A Credit Coin appears at the drop position, bobs, blinks in its last 3 s, disappears after 12 s of engine clock and disappears on a room change; it does not age while paused or while the menu is open.
- [ ] Collecting a coin plays `credit` once, fires `onCreditDrop` once and removes the coin.
- [ ] After a collected coin a signed-in player sees `CREDIT COIN +1 CREDIT`, the nav pill balance goes up by 1 and the game-over `+N CREDITS` includes it.
- [ ] `award_boss_credit('marcy-vampire-hunter', 'drop')` awards 1 credit and writes one `boss_awards` row with `boss = 'drop'`; the same call with any boss id raises `invalid_boss`; an unknown game id raises `unknown_game`.

- [ ] A banned user gets no credit and no notice.
- [ ] A failed network call shows nothing and does not block SAVE SCORE or PLAY AGAIN.
- [ ] The coin is not part of the password: `encodePassword` is unchanged and a password restore does not give coins.
- [ ] `credit` is the 19th effect, plays at volume 0.2 and is audibly different from the other effects; nothing plays while muted, paused or after game over.
- [ ] Asset URLs load through `withBasePath` (also under `/Arcade-Vault-Claude`).

## Decisions

- **Yes:** reuse the Pin Collection credits (the `CREDITS · NN` pill and `/pins`) as the reward (user request: "Credits for the collection list in the menu"). 1 credit per coin (user choice).
- **Yes:** reuse the RPC `award_boss_credit` with a new game id and `p_boss = 'drop'` (user choice). **No:** a new RPC with a separate table and tighter limits (the recommended option; not chosen). The cost of this choice is that drop credits and Robo Vault boss credits share the 3 s gap and the 30 per day cap.
- **Yes:** flat 0.1% per drop opportunity, on every enemy, breakable, chest and boss death (user choice). **No:** an LCK bonus or a pity timer.
- **Yes:** roll only for signed-in players, flat chance (user choice). **No:** letting guests see a coin they cannot keep.
- **Yes:** the credit is sent when the coin is collected. **No:** awarding when it drops (an expiring coin would give a free credit).
- **Yes:** `canDropCredit` as a callback read at each roll, because `GamePlayer` knows the session only after mount and the engine is created once.
- **Yes:** one extra roll beside the normal drops; chests and bosses keep their fixed rewards. **No:** changing any normal drop table.
- **Yes:** replace the SPEC 23 spells and familiars plan; they are out of scope and no spec is planned (user decision). SPEC 21 and SPEC 22 were updated to say so.
- **Yes:** the 26 password bits first reserved for spells and familiars stay spare. **No:** shrinking the grid or reusing them.

## Risks

| Risk                                                                                      | Mitigation                                                                                                                                               |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The server cannot verify a drop, so a modified client can call the RPC repeatedly.        | The existing 3 s gap and 30 per 24 h cap bound the abuse to 30 credits a day, the same exposure as Robo Vault boss credits; accepted by the user choice. |
| Shared cap: 30 Robo Vault boss credits in a day block Marcy drop credits and the reverse. | Rare (a full Robo Vault run gives 9); the notice stays silent on `daily_cap`, and the cap is documented in `CLAUDE.md`.                                  |
| 0.1% with many drop opportunities means a coin appears about once per 1,000 kills.        | Intended rarity; the Turned Castle has more kills. No change unless the user retunes `CREDIT_DROP_CHANCE`.                                               |
| The replaced function breaks Robo Vault boss credits.                                     | The migration keeps the Robo Vault validation as is; step 1 and the acceptance criteria re-check `('robo-vault', 'sam')` and the limits.                 |
| The Marcy `games` row does not exist yet when the migration is applied.                   | The migration is ordered after the SPEC 21 game migration (`boss_awards.game_id` references `games`); step 1 checks the row first.                       |
| A coin that is never collected looks like a lost reward.                                  | The 12 s lifetime and the blink are visible, and the pickup is placed where the enemy died.                                                              |
| Session `loading` at the first rolls reads as guest.                                      | `canDropCredit` is read at each roll, so rolls start working once the session is `ready`; a coin lost this way is accepted.                              |

## What is **not** in this spec

- Spells and familiars (out of scope, no spec planned).
- A new RPC or table, changes to the Robo Vault credit rules, guest credits.
- Boss credits for this game; LCK bonus, pity timer or a coin counter.
- Saving the coin in the password.
- Pins for this game, changes to the Pin Collection, `pull_pin` or `award_credit`.
- Automated tests.

Each one of those, if it lands, goes in its own spec.
