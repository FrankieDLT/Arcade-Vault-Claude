# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Arcade Vault: an online platform to play games and compete for the highest score. The project follows spec-driven development (`/spec` and `/spec-impl`, skills from `Klerith/fernando-skills`, installed with `npx skills@latest add Klerith/fernando-skills`). The README is written in Spanish.

Specs live in `specs/` (01 to 09, one per feature; the `add-game` skill writes game specs, `/spec-impl` implements them).

## App state

All UI text is English. Routes (App Router, `app/`):

- `/` home (`components/home.tsx`, data in `lib/home.ts`), `/library`, `/games/[id]` (detail + leaderboard), `/games/[id]/play` (`GamePlayer`), `/hall-of-fame`, `/auth`, `/about` (About + contact form), `not-found.tsx`.
- Contact form (`/about`): `components/contact-form.tsx` validates with `lib/contact.ts` and calls the Supabase Edge Function `contact` (`supabase/functions/contact/index.ts`). Honeypot, rate limit and Resend sending live in the function. There is no Next API route: the site is a static export.
- Auth is still a mock: `components/session-provider.tsx` keeps a name-only `SessionUser` in `localStorage` (`av_user`, via `lib/storage.ts`, with an in-memory fallback). Supabase Auth is not used.
- Catalog: `GAMES` in `lib/games.ts` (12 entries). The full list of games, which are implemented and which are catalog-only, is in `references/GAMES.md`.

## Commands

`npm run dev`, `npm run build`, `npm start`, `npm run lint` (eslint). Prettier is configured (`.prettierrc.json`). No test runner is configured.

## Configuration notes

- `next.config.ts` sets `output: "export"` (static site for GitHub Pages), `trailingSlash`, unoptimized images and `basePath` from `NEXT_PUBLIC_BASE_PATH` (empty locally). `cacheComponents` and `partialPrefetching` are OFF: Next fails the export with `PPR cannot be enabled in export mode`. `experimental.agentFeedback` is on. There is no server: no route handlers, cookies, server actions or `proxy.ts`.
- Tailwind v4 is wired through a Turbopack rule (`@tailwindcss/turbopack` on `*.css`), not PostCSS.
- Path alias: `@/*` maps to the repo root (not `src/`). Routes live in `app/` at the root.
- Supabase: the browser client is `getSupabase()` in `lib/supabase/client.ts` (lazy singleton built with `createBrowserClient` from `@supabase/ssr`). Import it from client components only. It throws, naming the variable, when `NEXT_PUBLIC_SUPABASE_URL` or `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` is empty. Both live in `.env` (documented in `.env.example`) and are inlined at build time, so restart `npm run dev` after editing. There is no server client, `proxy.ts` or service role key yet. `getSupabase()` returns `SupabaseClient<Database>`; the types in `lib/supabase/database.types.ts` are generated (MCP `generate_typescript_types`), never edited by hand.
- Database: tables `games` (seeded with the 9 original catalog games; `tetris`, `arkanoid` and `snake` were added by the `add_tetris_game`, `add_arkanoid_game` and `add_snake_game` migrations, so 12 rows) and `scores` (`game_id` FK to `games`, `name` 1-10 chars, `score` 0-10,000,000). RLS is on: public select on both, anonymous insert on `scores`, no update/delete. The schema lives in `supabase/migrations/` (file name = applied version); apply new migrations with MCP `apply_migration` and regenerate the types.
- Catalog sync: `GAMES` in `lib/games.ts` is still the UI source and the `games` table is a manual copy. A new game needs a migration that inserts its `games` row, otherwise its score insert fails on the foreign key. `asteroids`, `tetris`, `arkanoid` and `snake` all follow this (the last three via `supabase/migrations/20261105002355_add_tetris_game.sql`, `supabase/migrations/20261105012449_add_arkanoid_game.sql` and `supabase/migrations/20261105020551_add_snake_game.sql`; the snake file carries the version `apply_migration` assigned, not the one the spec proposed). Keep every field of the row identical to the `GAMES` entry, including `cover`.
- Score flow: `lib/scores-db.ts` has `fetchTopScores`, `fetchLatestScores`, `fetchTopScoresSince` and `insertScore` (client only). SAVE SCORE in `components/game-player.tsx` calls `insertScore` (anonymous, free-text name). There are no mock scores: `useTopScores` in `components/leaderboard.tsx` (used by `Leaderboard` and `HallOfFame`) returns only Supabase rows plus a `status` (`loading` / `ready` / `error`), `BestScore` (`components/best-score.tsx`) shows the top score per game on cards and the detail page (`—` when none), and `LiveActivity` (`components/home/live-activity.tsx`) feeds the home LATEST SCORES and TOP PLAYERS · TODAY. `lib/storage.ts` (`av_scores`) is no longer called for scores.
- Deployment: `.github/workflows/deploy-pages.yml` builds on push to `master` and publishes `out/` to https://frankiedlt.github.io/Arcade-Vault-Claude/ with `NEXT_PUBLIC_BASE_PATH=/Arcade-Vault-Claude` and the repo secrets `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Pages must use source "GitHub Actions" (not "Deploy from a branch", which serves the README). `next/link` adds the basePath itself; raw URL strings (audio, images) must go through `withBasePath()` from `lib/base-path.ts`. To test locally: build with `NEXT_PUBLIC_BASE_PATH=/Arcade-Vault-Claude` and serve `out/` under that folder. Contact form: the client calls the Supabase Edge Function `contact` (`supabase/functions/contact/index.ts`, `verify_jwt: false`, CORS limited to the Pages origin and localhost:3000) through `getSupabase().functions.invoke`. Its secrets `RESEND_API_KEY` and `CONTACT_TO_EMAIL` are set in the Supabase Dashboard. Next prefetch requests for `__next.*.txt` log harmless 404s on static hosts.

## Games

- The implemented (real) games are listed in `references/GAMES.md`; keep that file up to date when a game is added. Every other catalog game still runs the fake simulation (random score timer and a fake arena) inside `components/game-player.tsx`.
- Registry: `components/game-registry.tsx` maps a `gameId` to a `GameDefinition` (`Canvas`, `controls` for the hint under the CRT, `stats` = which of lives / lines / level the HUD shows, optional `music`, optional `appearance`, optional `sfx`, optional `levelSelect`, optional `linesLabel`). `getGameDefinition(gameId)` returns `undefined` for fake games. `GamePlayer` renders `<Canvas key={runId} />` from it instead of `.game-arena`, passes only the callbacks of the stats the definition uses (`GameCanvasProps`: `paused`, `endSignal`, `onScore`, `onGameOver`, optional `onLives`, `onLevel`, `onLines`, `skin` (a string id), `theme`, `onSound`, `levelRequest`), and shows LINES or LIVES in the same HUD slot (`linesLabel` replaces the `Lines` label, e.g. `Length`; the Level slot is hidden only when `stats.level === false`). PLAY AGAIN bumps `runId` to remount the canvas with a fresh engine. A new real game = an engine under `lib/<game>/`, a canvas wrapper, a registry entry and a `games` migration.
- Asteroids engine: `lib/asteroids/` (`constants.ts`, `utils.ts`, `entities.ts`, `engine.ts`). It is framework-free: no `react` or `next` imports, and no module-level game state. `AsteroidsEngine` draws on an 800x600 canvas, scaled by CSS.
- Engine contract: `new AsteroidsEngine(canvas, { onScore, onLives, onLevel, onGameOver })`, then `start()`, `pause()`, `resume()`, `end()`, `destroy()`. `onScore`, `onLives` and `onLevel` fire only when the value changes (`start()` fires 0, 3, 1). `onGameOver` fires once per run, and the engine then stops its loop and key listeners. The canvas draws only the playfield and power-up timers; score, lives, level and GAME OVER belong to the platform HUD and modal.
- `components/asteroids-canvas.tsx` is the thin client wrapper: it creates the engine once in an effect and destroys it on cleanup. Props: `paused`, `endSignal` (increment to call `end()`), and the callbacks (`onLives` and `onLevel` are optional).
- Tetris engine: `lib/tetris/` (`constants.ts`, `utils.ts`, `entities.ts`, `engine.ts`), same rules as asteroids (framework-free, no module-level state). `TetrisEngine` draws on a 440x600 canvas (board 300x600 on the left, a 120-wide column with NEXT and HOLD boxes on the right), shown with `object-fit: contain` so it letterboxes inside the 4:3 CRT. Pieces I O T S Z J L at random (no bag), hold (`S`), slow fall (hold `C`), ghost, scoring `[0,100,300,500,800] * level`, level = `1 + floor(lines / 10)`. Keys use `e.code`; `Space` and `S` ignore `e.repeat`; `P` and `Esc` do nothing (pause is the platform button).
- Tetris contract: `new TetrisEngine(canvas, { onScore, onLines, onLevel, onGameOver }, { skin?, theme? })`, then `start()`, `pause()`, `resume()`, `end()`, `destroy()`, plus `setSkin()` and `setTheme()` (redraw at once, also while paused or after game over). Callbacks fire only on change (`start()` fires 0, 0, 1); `onGameOver` fires once per run, then the key listeners are removed. Score is clamped to 10,000,000. The canvas draws the playfield and the NEXT / HOLD boxes only; score, lines, level, PAUSED and GAME OVER belong to the platform.
- Skins and theme: skins `retro`, `neon`, `pastel`, `pixel` (the `neon` colors are the page tokens `--cyan --yellow --magenta --green --bronze --silver --gold`) and themes `dark` / `light`, applied to the canvas only. A registry entry opts in with `appearance: { skins: { id: string; label }[], themes }` (ids are plain strings; each canvas wrapper narrows `skin` with a guard and falls back to its default); `GamePlayer` then owns `skin` (initialised from `skins[0].id`) and `theme` state (defaults `retro` / `dark`, in memory only, never in `localStorage`) and renders the SKIN and THEME buttons (`.appearance-row`) under the CRT.
- Music: a registry entry can set `music: { src, volume }`. `components/use-background-music.ts` (`useBackgroundMusic(music, { active, muted, restartKey })`) owns one looping `HTMLAudioElement` per mount; `GamePlayer` plays it while a run is active and not muted, and shows the mute button only for entries with `music` or `sfx`: its label is `MUSIC ON/OFF` when the entry has `music`, otherwise `SOUND ON/OFF`, and both share one `muted` state. Mute is in memory only. A blocked autoplay is retried once on the first key press or click. Tetris plays `public/game-assets/tetris/korobeiniki.mp3` at volume 0.2 (third-party recording: confirm its license before a public release). The engines stay silent.
- Sound effects: a registry entry can set `sfx: { sounds: Record<string, url>, volume }`. The engine emits `onSound(name)` and `components/use-sound-effects.ts` (`useSoundEffects(sfx, { muted })`, returns a stable `play(name)`) plays a `cloneNode()` of a lazily created `Audio` so fast hits overlap; it does nothing while muted. `GamePlayer` passes `onSound` only to entries with `sfx`.
- Level select: a registry entry can set `levelSelect: { min, max }`. While paused, the PAUSED overlay shows `LEVEL − NN +` (`.level-select`); each click sets `levelRequest = { level, id }` (new `id` per click, reset by PLAY AGAIN) and the canvas wrapper calls `engine.setLevel(level)`. Score and lives are kept.
- Arkanoid engine: `lib/arkanoid/` (`constants.ts`, `utils.ts`, `entities.ts`, `engine.ts`), same rules as asteroids (framework-free, no module-level state; the `SpriteSheet` lives in the engine instance). `ArkanoidEngine` draws on a 640x480 canvas scaled by CSS: 6x10 wall of 64x32 bricks from `y = 60`, paddle 100x12, ball 320 px/s base (+5% per level, capped at 2x), 3 lives, +10 per brick, endless levels from `generateLevel(level)` (seeded mulberry32, left-right symmetric), sub-stepped ball movement (`MAX_STEP = 8`). Power-ups (10% drop per brick): Triple ball, Complete bar (10 s), Frenzy (2x speed, 10 s). Input: `←` `→` / `A` `D`, mouse over the canvas, `Space` or click to launch; `P` and `Esc` do nothing.
- Arkanoid contract: `new ArkanoidEngine(canvas, { onScore, onLives, onLevel, onSound, onGameOver }, { skin? })`, then `start()`, `pause()`, `resume()`, `end()`, `destroy()`, plus `setSkin()` and `setLevel()` (both redraw at once, also while paused; `setLevel` clamps to 1..99 and is ignored after game over). Callbacks fire only on change (`start()` fires 0, 3, 1); `onSound("bounce" | "brick")` fires only from `update`; `onGameOver` fires once per run, then the key and mouse listeners are removed. Explosions use the engine clock, so they freeze while paused. Score is clamped to 10,000,000. The canvas draws the playfield and the `BAR Ns` / `FRENZY Ns` timers only; score, lives, level, PAUSED and GAME OVER belong to the platform. `components/arkanoid-canvas.tsx` is the wrapper (extra props `onSound`, `skin`, `levelRequest`). Skins `retro`, `pastel`, `neon` are CSS filters on the spritesheet (`public/game-assets/arkanoid/`, third-party assets: confirm their licenses before a public release); if the sheet fails to load the game runs with flat shapes and logs one console error.
- Snake engine: `lib/snake/` (`constants.ts`, `utils.ts`, `entities.ts`, `engine.ts`), same rules as asteroids (framework-free, no module-level state; the `SpriteSheet` lives in the engine instance). `SnakeEngine` draws on an 800x600 canvas scaled by CSS: a 20x15 grid of 40 px cells, snake starts at length 3 (head col 10, row 7, heading right), fixed-step ticks at `min(16, 8 + 0.4 * fruitsEaten)` per second, no levels or lives. One regular fruit (+10, grows by 1, random sprite of the 22 in `FRUIT_SPRITES`, never the same twice in a row) and a golden bonus (15% after each regular fruit, +50, 6 s of game time, blinks the last 2 s, `pineapple` sprite with a shrinking ring). Walls and the body kill; moving into the cell the tail leaves on that tick is allowed; filling all 300 cells ends the run through `onGameOver`. Input: arrows / `WASD` through `e.code`, a 2-slot direction queue (no duplicates, no 180 degree turns, `e.repeat` ignored); `P` and `Esc` do nothing. Only a `keydown` listener exists (no held keys).
- Snake contract: `new SnakeEngine(canvas, { onScore, onLength, onGameOver }, { skin? })`, then `start()`, `pause()`, `resume()`, `end()`, `destroy()`, plus `setSkin()` (redraws at once, also while paused). Callbacks fire only on change (`start()` fires 0, 3); `onGameOver` fires once per run, then the key listeners are removed. Score is clamped to 10,000,000. The canvas draws the playfield, the fruit, the bonus and its ring only; score, length, PAUSED and GAME OVER belong to the platform. `components/snake-canvas.tsx` is the wrapper (`onLength` arrives as the `onLines` prop). The registry entry sets `stats: { lives: false, lines: true, level: false }` and `linesLabel: "Length"`, so the HUD shows Score and LENGTH. Skins `retro`, `neon`, `pastel` (board and snake palettes plus a CSS filter on the fruit sprites, no theme) come from `SKINS` in `constants.ts`. Fruit art is `public/game-assets/snake/fruits.png` (third-party, The Spriters Resource / Google Snake game: confirm its license before a public release); if it fails to load the game runs with flat circles and logs one console error.

## Design reference

`references/templates/` holds the UI prototype that was ported, not app code: `Arcade Vault.html` plus `.jsx` files (`app`, `auth`, `biblioteca`, `data`, `detalle`, `nav`, `reproductor`, `salon`), `styles.css`, and `home-about/` (home and About prototypes). Mock data is in `data.jsx`. `references/StarterGames/` holds the vanilla-JS sources of asteroids, tetris and arkanoid; `references/source-assets/snake-assets` holds the snake art sources. `resources/` holds only a raw copy of the Tetris music (the served file is in `public/game-assets/tetris/`).

## Skills

Always use /frontend-design when developing user interfaces.

The `game-planner` agent (`.claude/agents/game-planner.md`) suggests new games that fit the library; its log of past suggestions is `references/game-suggestions-todo.md`.

The `game-jam` agent (`.claude/agents/game-jam.md`) takes a theme and writes one original game as 3 spec variants (`v1-lean.md`, `v2-standard.md`, `v3-deluxe.md`) plus a `README.md` index in `references/gameJam/<game-id>/` for review. It only writes in that folder; a chosen variant is promoted by copying it to `specs/NN-<id>-game.md`.

When using Playwright, always leave all screen captures taken in the same ".pwScreencaps" folder in the root directory
