# CLAUDE.md

Guidance for Claude Code (claude.ai/code) in this repo.

## Project

Arcade Vault: online platform to play games and compete for high score. Spec-driven: `/spec` and `/spec-impl` (skills from `Klerith/fernando-skills`, install with `npx skills@latest add Klerith/fernando-skills`). README is Spanish. All UI text is English.

Specs in `specs/` (01 to 12, one per feature). `add-game` skill writes game specs, `/spec-impl` implements them.

## App state

Routes (App Router, `app/`): `/` home (`components/home.tsx`, data `lib/home.ts`), `/library`, `/games/[id]` (detail + leaderboard), `/games/[id]/play` (`GamePlayer`), `/hall-of-fame`, `/pins` (Pin Collection, spec 18), `/auth` (sign in / register), `/auth/forgot`, `/auth/reset`, `/account`, `/about` (About + contact form), `not-found.tsx`.

- Contact form: `components/contact-form.tsx` validates with `lib/contact.ts`, calls Supabase Edge Function `contact` (`supabase/functions/contact/index.ts`). Honeypot, rate limit, Resend sending live in the function. No Next API route: site is static export.
- Auth is real Supabase Auth (spec 13), all in the browser (static export: no cookies, no server). Email + password, Google, GitHub. `components/session-provider.tsx` reads the session (`onAuthStateChange`) and exposes `{ user, status, signOut }`: `user` is `SessionUser { name, email, provider, hasPassword }`, `status` is `loading` / `ready` / `unavailable` (missing env vars: site acts as guest). Guest = no session. Server render and first client render are `loading` with `user: null` (no hydration mismatch). `av_user` and `lib/storage.ts` user helpers are gone.
  - Files: `lib/auth.ts` (framework-free validators, `deriveUsername`, `safeNextPath`, `authErrorMessage`), `lib/auth-redirect.ts` (`sessionStorage` key `av_auth_next`, return-to page after sign in), `components/auth-form.tsx`, `forgot-form.tsx`, `reset-form.tsx`, `account-panel.tsx`, shared `auth-ui.tsx` (`AuthCard`, `Field`). The nav `Sign in` link and the game-over `SIGN IN` link write `av_auth_next`; `/auth` reads it with `takeNextPath()` and `safeNextPath` (same-site paths only, never `/auth*`).
  - Username: `user_metadata.username` (uppercase, 1-20 chars, `A-Z 0-9 _ -`), not unique. The score name is the username cut to 10 chars (`scores.name` limit). OAuth users: derived from provider name (`deriveUsername`), not written back. Changed on `/account`. `/account` password form also lets OAuth-only users set a first password. Signup with `identities: []` and no session = email already registered (shown as error).
  - OAuth `redirectTo` = `<origin><basePath>/auth/`, reset `redirectTo` = `<origin><basePath>/auth/reset/` (built with `withBasePath`).
  - Supabase Dashboard settings (cannot be set from code or MCP): Site URL `https://frankiedlt.github.io/Arcade-Vault-Claude/`; redirect allow-list `https://frankiedlt.github.io/Arcade-Vault-Claude/**` and `http://localhost:3000/**`; Email provider on, `Confirm email` OFF, min password length 8; Google and GitHub providers with client ID and secret; `Allow anonymous sign-ins` OFF; `Secure password change` OFF; sign up / sign in rate limit 10 per 5 minutes per IP (Authentication > Rate Limits). Supabase rejects `@example.com` emails and its built-in mailer allows only a few emails per hour.
- Pin Collection (spec 18): `/pins` = candy-dispenser machine (`components/pin-machine.tsx`, pure CSS/DOM) above an almanac of 215 pins (`components/pin-almanac.tsx`; unowned cards render only number, silhouette and `???`, never name, rarity or game). State: `components/pin-collection.tsx` (owned set), `components/credits-provider.tsx` (`useCredits()` = `{ balance, status, refresh, setBalance }`, mounted in `app/layout.tsx`, 0 for guests), client data `lib/pins-db.ts` (`fetchCredits`, `fetchOwnedPins`, `awardCredit`, `pullPin`, `PinsError` kinds `insufficient` / `collection_complete` / `signin` / `network`). Nav pill `CREDITS · NN` (`99+` above 99) links to `/pins`; tab `Pin Collection` sits between Hall of Fame and About.
  - Machine (SPEC 26): the lever `.pm-lever` is a real `<button>` (`Pull the crank`, click / tap / `Enter` / `Space`, 56 px+ hit area) and the only trigger. The three costs are a radio group (`.pm-dial`, `role="radiogroup"`, three `role="radio"` coins, arrow keys move the selection, selecting never pulls). The selection is derived in `components/pin-machine.tsx` from memory-only `choice` state: the pick while affordable, else 5, and after a pull the highest affordable option; none under 5 credits (crank disabled, `Not enough credits. Finish a game to earn more.`); `100` is also disabled when the collection is complete; guests get crank and selector disabled plus the sign-in link. Sounds in `lib/pins/sfx.ts` (Web Audio synthesis, no files): `playCrankTick()` at the click (stops anything playing), `playCrank(rarity)` when the result arrives, `playReveal(rarity)` at the reveal, `setPinSfxMuted()`; `PIN_SFX_TIERS` grows strictly with rarity (reveal 0.6 / 0.9 / 1.3 / 1.8 / 2.5 s). The `AudioContext` is created lazily in the crank click, every call is a no-op without Web Audio. `SOUND ON/OFF` toggle in `.pm-controls`, default ON. Neither the selected cost nor the toggle is stored anywhere.
  - Credits: Credits come from play time: 1 credit per 30 s played, at most 5 per game (migration `award_credit_by_play_time`). `GamePlayer` counts active play seconds (`playedMs`: not paused, not over, tab visible, not on the mode picker), calls `awardCredit(gameId, score, seconds)` once per run at Game Over (signed-in, score > 0) and shows `+N CREDITS` when the server awards. Server rule (RPC `award_credit(p_game_id, p_score, p_seconds)`): score 1..10,000,000, game exists, not `profiles.banned`, `credits = least(5, floor(seconds / 30))` where seconds is capped at 3600 and at the real time since `credits.last_award_at` (a forged value cannot beat real time); reasons `ok` / `zero_score` / `banned` / `too_short`. A failed call shows nothing.
  - Boss credits (Robo Vault, migrations `award_boss_credit` and `award_boss_credit_min_interval`): every boss defeated earns 1 credit for a signed-in player: each Master stage boss, each rematch boss in castle room 2 (`rematch:<id>`) and Sam's final phase (`sam`, once); 9 per full run. The engine calls `onBossDefeated(boss)`, `GamePlayer` calls `awardBossCredit(gameId, boss)` (`lib/pins-db.ts`), updates the nav balance and shows a `BOSS DEFEATED +1 CREDIT` notice over the CRT; the game-over `+N CREDITS` adds play-time and boss credits. RPC `award_boss_credit(p_game_id, p_boss)` (security definer, execute for `authenticated` only, `robo-vault` only, boss id validated by regex): the server cannot verify a fight, so it rate-limits through table `boss_awards` (RLS on, no policy, no client access): at least 3 s between boss awards and at most 30 per rolling 24 h per user, banned users get nothing (reasons `ok` / `banned` / `too_soon` / `daily_cap`). It does not touch `credits.last_award_at` (the play-time award's clock). Guests earn nothing. The advisor warning for this definer function is accepted (like `award_credit`), plus the `rls_enabled_no_policy` INFO for `boss_awards`.
  - DB (migration `add_pin_collection`): `pins` (151 rows in `add_pin_collection`, 215 after `add_pins_new_games`, public select), `credits` (`balance`, `last_award_at`), `user_pins` (PK `(user_id, pin_id)`: one copy, duplicates are never stored). RLS: a user reads only own `credits` / `user_pins` rows; no client write on any of them. Only RPCs `award_credit` (above) and `pull_pin(p_cost in 5,10,100)` (security definer, execute for `authenticated` only) change them. `pull_pin` locks the credits row; 5 = table 60/20/15/4/1, 10 = 40/25/22/10/3 with one reroll on owned, 100 = random unowned pin of the lowest rarity left (`collection_complete` error when none); duplicate refund common 1, rare 2, super rare 3, ultra rare 5, epic 10. Banned users can still pull. Advisor warnings for the two executable definer functions are accepted (like `royalty_of_games`).
  - Catalog sync: `PINS` in `lib/pins/catalog.ts` is a manual copy of the `pins` table (id, number, game, name, kind, rarity); change both together. Counts 121 common / 44 rare / 34 super rare / 12 ultra rare / 4 epic (215). 79 pins come from sprites of real games (Space Voyage, Wall Wrecker, Snake, Glowmaw, Street Jumper, Alien Attack, Galactic DogFight), 72 are generic common fillers, and 64 (numbers 152 to 215, migration `add_pins_new_games`) come from Robo Vault (20), Marcy the Vampire Hunter (20), Wingshot (12), Super Tennis (4) and Block Rain (8); the epics are Alien Attack Bonus Saucer, Marcy Delrre, Frankford Delrre and the Orbit Astronaut. The Super Tennis and Block Rain pins are drawn for the pin only (the engines have no sprites). Sprites are 16x16 run tables in `lib/pins/sprites.ts` (redrawn, no `public/game-assets/` art; at most 6 colors), drawn once by `components/pin-sprite.tsx` (`silhouette` prop). The Alien Attack Bonus Saucer pin (epic) has no sprite in the engine; it is drawn for the pin only.

  - Origin (spec 19): every `Game` has a required `origin: "ai" | "human" | "assisted"`. `ORIGINS` in `lib/games.ts` maps it to emoji, tag text and accessible name (`🤖 A.I MADE`, `🧑 HUMAN MADE`, split `A.I. ## Games

Real games: `references/GAMES.md` (keep updated when a game is added). Every catalog game is real: `GamePlayer` has no fake simulation, and `getGameDefinition(gameId)` returns a definition for every `GAMES` entry.

New real game = engine in `lib/<game>/`, canvas wrapper, registry entry, `games` migration. Pipeline: `/full-game-impl`. Manual, human-oriented walkthrough: `GAME-INTEGRATION-GUIDE.md` (repo root).

### Registry and player

- `components/game-registry.tsx` maps `gameId` to `GameDefinition`: `Canvas`, `controls` (hint under CRT), `stats` (which of lives / lines / level HUD shows), optional `music`, `appearance`, `sfx`, `levelSelect`, `modes`, `difficultySelect`, `linesLabel`, `touch`. `getGameDefinition(gameId)` returns `undefined` for fake games.
- `GamePlayer` renders `<Canvas key={runId} />` instead of `.game-arena`. Passes only callbacks of stats the definition uses (`GameCanvasProps`: `paused`, `endSignal`, `onScore`, `onGameOver`, optional `onLives`, `onLevel`, `onLines`, `skin` (string id), `theme`, `onSound`, `levelRequest`, `mode`, `difficulty`). LINES or LIVES share one HUD slot; when `stats.lives` and `stats.lines` are both false (Super Tennis) neither shows. `linesLabel` replaces `Lines` (e.g. `Length`). Level slot hidden only when `stats.level === false`. PLAY AGAIN bumps `runId`: fresh engine.
- Modes: registry `modes: { id, label, hint }[]` opts in. `GamePlayer` starts with `mode = null`: the CRT shows the mode picker (`.mode-picker`), no canvas, PAUSE / END / pad disabled. Picking a mode calls the same reset as PLAY AGAIN and mounts `<Canvas mode difficulty />` (`mode` only sent to entries with `modes`). PLAY AGAIN keeps the mode; the GAME OVER modal shows `CHANGE MODE` (back to the picker, fresh run) only for entries with `modes`. Memory only.
- Difficulty: registry `difficultySelect: { options, default, onlyModes }`. While paused and `mode` is in `onlyModes`, the overlay shows the options (`.level-select.opt-select`, `.ls-opt`). `difficulty` state is memory only, kept by PLAY AGAIN; the canvas wrapper calls `engine.setDifficulty` in an effect; a different difficulty restarts the match (score, lives, positions reset, no-op for the active one).

### Engine rules (all games)

- Engine in `lib/<game>/` (`constants.ts`, `utils.ts`, `entities.ts`, `engine.ts`). Framework-free: no `react` or `next` imports, no module-level game state. Exception (SPEC 27): a Java game keeps its engine in `java/<id>/`, compiled to `public/game-assets/<id>/<id>.js`; `lib/<id>/` then holds only TypeScript glue (canvas size, skin palettes, skin guard). See Java games.
- Contract: `new XEngine(canvas, callbacks, { skin?, theme? })`, then `start()`, `pause()`, `resume()`, `end()`, `destroy()`, plus `setSkin()` (redraws at once, also paused or after game over). Some add `setTheme()`, `setLevel()`.
- Callbacks fire only on change. `start()` fires initial values (typically 0, 3, 1). `onGameOver` fires once per run, then loop and listeners stop. Score clamped to 10,000,000.
- Canvas draws playfield only (plus in-game timers). Score, lives, level, PAUSED, GAME OVER belong to platform HUD and modal.
- Keys via `e.code`. `P` and `Esc` do nothing: pause is platform button.
- Wrapper `components/<game>-canvas.tsx`: creates engine once in effect, destroys on cleanup. Narrows `skin` string with guard, falls back to default.
- Canvas scaled by CSS. Sizes: space-voyage, snake, glowmaw, super-tennis, alien-attack, dot-catcher 800x600; block-rain 440x600; galactic-dogfight 480x600; wall-wrecker 640x480; street-jumper 640x560. Non-4:3 canvases use `object-fit: contain`.
- Engines never play sound or vibrate. They emit `onSound(name)`, `onHaptic(name)`. Platform decides.

### Per-game notes

- Space Voyage: `SpaceVoyageEngine`, callbacks `onScore onLives onLevel onGameOver`. Skins `retro neon pastel gothic negative amber-crt deep-sea` (palettes in `SKINS`; `neon`, `amber-crt` add canvas glow). Wrapper props: `paused`, `endSignal` (increment calls `end()`), callbacks. Haptic `split`.
- Block Rain: `BlockRainEngine`, callbacks `onScore onLines onLevel onGameOver`, `start()` fires 0, 0, 1. Canvas: board 300x600 left, 120-wide NEXT / HOLD column right. Random pieces (no bag), hold `S`, slow fall `C`, ghost. Score `[0,100,300,500,800] * level`, level `1 + floor(lines / 10)`. `Space` and `S` ignore `e.repeat`. Skins `retro neon pastel gothic negative woodshop ice-cavern pixel` + themes `dark` / `light` (canvas only; per-theme colors from `getThemeColors(skin, theme)`, `SKIN_THEME_OVERRIDES` in `constants.ts`). `neon` colors = page tokens `--cyan --yellow --magenta --green --bronze --silver --gold`. Haptics `clear`, `quad` (4 lines).
- Wall Wrecker: `WallWreckerEngine`, callbacks add `onSound("bounce" | "brick")` (only from `update`). 6x10 wall of 64x32 bricks, ball 320 px/s (+5% per level, cap 2x), endless levels from seeded `generateLevel(level)`, sub-stepped ball (`MAX_STEP = 8`). Power-ups (10% drop): Triple ball, Complete bar (10 s), Frenzy (2x speed, 10 s). Input: `←` `→` / `A` `D`, pointer on canvas (mouse, touch, pen), `Space` or click/tap launches. `setLevel` clamps 1..99, ignored after game over. Explosions use engine clock: freeze while paused. Art is original and drawn in code (SPEC 26): `buildArt(skin)` in `lib/wall-wrecker/entities.ts` pre-renders bricks, paddle, ball, capsules and explosion frames into offscreen canvases per skin (cached in the engine, one `drawImage` per sprite per frame); no image file. Skins `retro pastel neon` are palettes in `SKINS` (`constants.ts`; `neon` adds a glow). Sounds `ball-bounce.wav` and `break-sound.wav` in `public/game-assets/wall-wrecker/` are generated (generator not shipped). Extra wrapper props `onSound`, `skin`, `levelRequest`. Haptics reuse `onSound("brick")`.
- Snake: `SnakeEngine`, callbacks `onScore onLength onGameOver`, `start()` fires 0, 3. 20x15 grid of 40 px cells, starts length 3, ticks at `min(16, 8 + 0.4 * fruitsEaten)`/s, no levels or lives. Fruit +10, grows 1, 22 fruit sprites (`FRUIT_SPRITES` in `lib/snake/sprites.ts`), never same twice. Golden bonus: 15% after each fruit, +50, 6 s, blinks last 2 s. Walls and body kill; entering the cell the tail leaves is allowed; full grid (300) ends run. 2-slot direction queue (no duplicates, no 180 turns). `keydown` only. Listener helpers in `Browser.java` must take the `@JSFunctor` type, not `JSObject`, or the lambda is never converted and the listener never fires. Palettes belong to TypeScript (`SKINS`) and reach Java as a plain object, so `skin-designer` works unchanged and a new skin needs no rebuild.
- Pipeline overrides for a Java game: the engine location is `java/<id>/src/main/java/...`; a stage that edits it runs `npm run build:java` and keeps the rebuilt `.js` in the same change.

### Appearance, audio, level select

- Skins and themes: registry `appearance: { skins: { id: string; label }[], themes }` opts in. `GamePlayer` then owns `skin` (init from `skins[0].id`) and `theme` state (defaults `retro` / `dark`, memory only, never `localStorage`) and renders SKIN and THEME buttons (`.appearance-row`) under CRT. Themes apply to canvas only.
- Music: registry `music: { src, volume }`. `components/use-background-music.ts` (`useBackgroundMusic(music, { active, muted, restartKey })`) owns one looping `HTMLAudioElement` per mount. Plays while run active and not muted. Blocked autoplay retried once on first key press or click. Block Rain: `public/game-assets/block-rain/korobeiniki.mp3`, volume 0.2 (third-party: confirm license before public release).
- Mute button shows only for entries with `music` or `sfx`. Label `MUSIC ON/OFF` if `music`, else `SOUND ON/OFF`. One shared `muted` state, memory only.
- Sound effects: registry `sfx: { sounds: Record<string, url>, volume, pauseToggle? }` (`pauseToggle` adds a `SOUND ON/OFF` button to the PAUSED overlay, same shared `muted` state; only Super Tennis sets it). `components/use-sound-effects.ts` (`useSoundEffects(sfx, { muted })`) returns stable `play(name)`, plays `cloneNode()` of lazy `Audio` so hits overlap, nothing while muted. `GamePlayer` passes `onSound` only to entries with `sfx`.
- Level select: registry `levelSelect: { min, max }`. While paused, overlay shows `LEVEL − NN +` (`.level-select`). Each click sets `levelRequest = { level, id }` (new `id` per click, reset by PLAY AGAIN); wrapper calls `engine.setLevel(level)`. Score and lives kept.
- Third-party assets: only the Block Rain music (`korobeiniki.mp3`) remains and stays flagged: confirm its license before public release. The Wall Wrecker sheet and sounds and the Snake fruit sheet were replaced by original art and generated sounds in SPEC 26.

### Touch, gamepad, haptics (specs 10, 11)

- Registry `touch: { pad?: TouchButton[], swipe?, hint }`. `TouchButton = { code, label, hold?, slot: PadSlot }`. `PadSlot` (from `lib/gamepad.ts`) = `up down left right a b x y`. A code may sit in two slots (Block Rain `up` and `a` both `ArrowUp`). Real games with `pad`: Block Rain, Space Voyage, Glowmaw, Street Jumper, Alien Attack, Galactic DogFight, Robo Vault, Marcy the Vampire Hunter, Dot Catcher (`left`/`right` hold), Super Tennis (`up`/`down` = `KeyW`/`KeyS`, `a`/`b` = arrows). Snake: `swipe`. Wall Wrecker: `hint` only.
- Touch UI (hint, haptics, forced-on pad) active only below 768px. Keep `TOUCH_UI_QUERY` in `components/use-touch-ui.ts` and `@media (max-width: 767px)` rules in `app/globals.css` in sync.
- `components/touch-pad.tsx` (`TouchPad`: `buttons`, `skin`, `disabled`, `onPress`): each press sends one synthetic `keydown` on `window` (same `code` engines read), each release one `keyup`. Engines have no touch-specific input. Pointer capture + one `pointerId` per control = multi-touch. Releases held keys on pointerup / cancel / leave / lost capture, hidden page, blur, `disabled` (pause, game over), cross/joystick change, unmount. Code held by two controls: one `keydown`, one `keyup` (when last released). Direction controls auto-repeat: after `REPEAT_DELAY_MS = 167` send `keydown` with `repeat: true` every `REPEAT_INTERVAL_MS = 33`, until release. Timers per control and code. Action buttons (A B X Y) never repeat.
- GamePad menu: `components/gamepad-menu.tsx`, top-bar button + dropdown (ON/OFF switch, 4 skins; closes on `Esc`, outside click, route change; typed keys do not reach game). `Nav` renders it only on `/games/<id>/play` when `getGameDefinition(id)?.touch?.pad` exists. State in `GamepadProvider` (`components/gamepad-provider.tsx`, mounted in `app/layout.tsx`, read with `useGamepad()`): `{ enabled, skin }`, memory only, default `false` / `neon`. Below 768px pad always shown, switch ON and locked (`Always on for touch screens`). At 768px+ pad hidden until switch ON; keyboard hint stays. `GamePlayer` renders `TouchPad` when `touch.pad` exists and (`touchUi || enabled`). `useTouchUi()` uses `matchMedia` through `useSyncExternalStore`.
- Gamepad skins: `lib/gamepad.ts` (framework-free): `GamepadSkinId` (`neon` default, `retro`, `arcade-80s`, `wood`), `GAMEPAD_SKINS`, `PadSlot`, `usesJoystick(skin)`. Pure CSS on `.touch-pad.skin-<id>` (`app/globals.css`; PNGs in `references/gamepad-assets/` not shipped). Markup: `.tp-dpad` (cross: `up left hub right down`) or `.tp-dir > .tp-stick` (joystick) | `.tp-actions` (`a`, `b`, plus four inert `.tp-deco` in arcade skins) | `.tp-pills` (`x`, `y`). Unmapped slot: dimmed, `aria-hidden`, not focusable, no pointer events. Joystick (arcade skins): pointer angle to 8 sectors, 28% dead zone, up to two arrow codes, only sends codes of mapped direction slots. Live controls at least 56px tall.
- `components/use-swipe-controls.ts` (`useSwipeControls(ref, { enabled, onSwipe })`, used by `snake-canvas.tsx`): 24 px swipe in dominant axis sends synthetic arrow `keydown`/`keyup`. Origin resets after each trigger. Touch and pen only (mouse ignored). `touch-action: none` on target.
- Wall Wrecker listens to `pointermove` / `pointerdown` on canvas: drag moves paddle, tap launches. All canvases and pad have `touch-action: none` in CSS. Controls hint rendered twice for entries with `touch` (`.controls-hint-keys`, `.controls-hint-touch`), CSS swaps them.
- Haptics: `lib/haptics.ts` (framework-free) owns `HAPTIC_PATTERNS` (`tap gameover brick clear quad split fruit bonus pearl death`) and `haptic(kind)`. Does nothing without `navigator.vibrate` (iOS Safari has none) or under `prefers-reduced-motion: reduce`. Never throws. `GamePlayer` calls `haptic` only when touch UI active, `navigator.vibrate` exists and toggle ON. `tap` on pad presses, Snake swipes, Wall Wrecker touch-downs. `gameover` on game over. `HAPTICS ON/OFF` button in `.appearance-row`: only below 768px with `navigator.vibrate` (read via `useSyncExternalStore`, no hydration mismatch), memory only, survives PLAY AGAIN.

## Security (spec 14)

- Referrer policy ships as `<meta name="referrer">` through `metadata.referrer` in `app/layout.tsx`.
- `headers()` in `next.config.ts` does not work with `output: "export"` (errors in `next dev`) and GitHub Pages sends no custom headers. `X-Frame-Options`, `X-Content-Type-Options` and CSP `frame-ancestors` are ignored in `<meta>`: do not add them there.
- Next.js Proxy (`proxy.ts`) is unsupported on static export, and the session is in browser storage, not cookies. Do not add `proxy.ts` or `middleware.ts`.
- The `/account/` redirect to `/auth/` (`components/account-panel.tsx`) is a client guard for UX only. Real data protection is RLS.
- Leaked password protection needs Supabase Pro; project is on Free, so the advisor warning `auth_leaked_password_protection` is accepted.
