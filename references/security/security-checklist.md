## Checklist de seguridad básico

  - [x] RLS: Row Level Security habilitado en ambas tablas: `games` y `scores`. Hecho (SPEC 14): insert de `scores` solo para usuarios con sesión, migración `require_signin_to_save_scores`; `anon` rechazado por REST (401, `42501`). El advisor `rls_policy_always_true` ya no aparece.
  - [ ] Minimum password length — mínimo 8 caracteres. PENDIENTE (Dashboard): el 2026-11-10 una contraseña de 7 caracteres con todas las clases (`Abcd12!`) fue aceptada por `signUp`. El código (`PASSWORD_MIN` en `lib/auth.ts`) ya exige 8 en el formulario; falta subir el mínimo en Authentication > Providers > Email.
  - [ ] Leaked password protection — (el warning 4). BLOQUEADO: requiere el plan Pro de Supabase y el proyecto está en Free. Warning aceptado.
  - [ ] Max signup rate — limitar signups por IP (anti-bot). PENDIENTE (Dashboard): Authentication > Rate Limits > "Rate limit for sign ups and sign ins" = 10 cada 5 minutos por IP. No se puede cambiar por MCP.
  - [ ] Headers de seguridad en Next.js. Parcial: `Referrer-Policy` hecho como `<meta name="referrer">` (campo `referrer` de `metadata` en `app/layout.tsx`). BLOQUEADO: `X-Content-Type-Options` y `X-Frame-Options`; `headers()` no funciona con `output: "export"` y GitHub Pages no envía headers propios; los navegadores ignoran estos dos en `<meta>`.
  - [ ] Protección de rutas con Next.js Proxy (`proxy.ts`). BLOQUEADO: no soportado con `output: "export"`, no hay servidor en GitHub Pages y la sesión vive en el navegador, no en cookies. Solo existe el guard del cliente en `/account/` (solo UX; la protección real es RLS).
  
  Ej:

```ts
const securityHeaders = [
  { key: 'X-Content-Type-Options', value: 'nosniff' },
  { key: 'X-Frame-Options', value: 'DENY' },
  { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
];

// En la config de Next.js:
headers: async () => [
  { source: '/(.*)', headers: securityHeaders }
]
```
